## 1. `packages/ui-spec/components/data-grid/api.yaml`

### 1a. `row-id` — shipped, and conditional

**Replace** the `- name: row-id` block (`:16-22`):

```yaml
    - name: row-id
      type: 'RowIdResolver<Row>'
      required: true
      description: >-
        Target P0. Required by the new grouped API. The deprecated identity-free
        React overload may omit it for one minor line, but identity features
        then warn and cannot reserve across data windows.
```

**with**:

```yaml
    - name: row-id
      type: 'RowIdResolver<Row>'
      required: true
      description: >-
        Shipped, conditionally required per the identity rule. Required as soon
        as an identity-bearing feature is enabled — selection, actions, current
        row, server mode, or a controlled selection/current-row/detail-expanded/
        tree-expanded slice — and optional only while all of them are disabled.
        Sorting, filters, pagination, appearance and the toolbar need no row
        identity and do not require it. Row click/hover/activate handlers receive
        the row object rather than an id and do not require it either; only the
        current row does. The React adapter enforces this with a discriminated
        props union, so omitting it is a compile error. The deprecated flat
        aliases stay source-compatible for one minor line: they warn that
        identity falls back to the row index and cannot survive a data change.
```

### 1b. `state` / `defaultState` — shipped, with the two precedence rules

**Replace** the `- name: state` and `- name: defaultState` blocks (`:23-30`):

```yaml
    - name: state
      type: 'Partial<DataTableState<RowId>>'
      required: false
      description: Controlled slice values; wins over defaultState and config defaults.
    - name: defaultState
      type: 'Partial<DataTableState<RowId>>'
      required: false
      description: Initial uncontrolled slice values; wins over config defaults.
```

**with**:

```yaml
    - name: state
      type: "DataStatus | Partial<DataTableState<RowId>>"
      required: false
      description: >-
        Shipped. Controlled slice values; wins over defaultState and config
        defaults. A slice present here is controlled: a requested change emits
        the callbacks but is not committed internally. Server mode controls the
        query slices exclusively, so also controlling one of those is reported.
        The React adapter additionally accepts the deprecated data-status string
        under this name as the alias for dataState.status; the two forms are
        structurally disjoint and the string is removed next major.
    - name: defaultState
      type: 'Partial<DataTableState<RowId>>'
      required: false
      description: >-
        Shipped. Initial uncontrolled slice values, read once; wins over config
        defaults, so defaultState.pagination beats pagination.pageSize. The same
        slice in both state and defaultState is a development error and the
        controlled value wins.
```

## 4. Needs a ruling: the spec overstates the identity rule

`context/table-feature-parity-design.md` §3.1 contains two rules that do not
agree, and `packages/ui-spec` encodes the stronger one:

- **Bullet 3** says DataGrid's grouped API *"always requires `row-id`"*.
- **The React enforcement block directly below it** specifies a discriminated
  options union whose identity-free branch permits `state`, `defaultState`,
  `getSubRows` and every non-identity feature — i.e. a **conditional** rule.

`api.yaml:16-22` and `behavior.md:150-155` both encode "always".

**F5 implemented the conditional rule**, because "always" is not implementable for
a JSX component without absurd collateral: DataGrid has one props interface and no
overloads, so the only way to express "the grouped API always requires `row-id`" is
to make the identity-free branch reject *every* grouped prop — which would force
`getRowId` on `<DataGrid columns rows sorting={{ mode: 'single' }} />`. Sorting
carries no row identity. Requiring it there buys nothing and breaks the identity-free
case the design's own union exists to preserve.

The blocks in §1a and §2a above are written for the conditional rule. **If the
architect rules the other way, F5's props union needs revisiting, not just the
spec** — flagging rather than assuming, since this is design text and not mine to
change. My read is that bullet 3 is loose prose and the union block is normative;
one sentence in §3.1 would settle it.

One documented ergonomic caveat: for **JSX**, the error is ideal (`Property
'getRowId' is missing … but required in type 'DataGridIdentityProps<Person>'`). For
a bare `const x: DataGridProps<…> = { … }` annotation the rule still rejects the
object, but TS reports it against a member of the offending config rather than
against `getRowId`. JSX is the real usage; the caveat is worth knowing, not fixing.
