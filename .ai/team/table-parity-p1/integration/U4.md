## Two foreign files U4 edited under a granted ruling

Recorded here because a reviewer will otherwise see them as out-of-scope.

1. **`data-table-features/tree.ts`** (U2's) — the `getExpandedRowModel`
   contribution is **removed**. One stage, two features, and
   `composeEngineOptions` throws if both claim it. A dynamic handover is
   impossible: `table.getExpandedRowModel()` resolves the option **once** and
   caches it on `table._getExpandedRowModel`, which nothing clears, so a table
   that starts ungrouped keeps whichever model it got first. Grouping's model is
   a strict superset — it asks `row.getIsExpanded()` for every non-group row —
   so tree loses nothing. Asserted across a grouping change in both directions in
   `data-table/__tests__/data-table-grouping.test.tsx`.
2. **`data-table-controller.ts`** — the pre-declared `toggle-group` arm is wired
   to the new `groupCollapsed` slice, scoped to that arm alone. It previously
   threw "requires the grouping feature, which is not implemented yet", which
   becomes false the moment the feature ships.

## One shared test fake U4 corrected

`data-table/__tests__/data-table-features.test.tsx`'s `fakeContext()` had
`state: {} as never`. The controller always hands modules a **complete** state
(`createDefaultDataTableState`), and `grouping.tsx` legitimately reads
`state.grouping` in `engineOptions` to decide whether to install the grouped row
model — so the empty cast made the fake the only place that shape could occur, and
it failed with a bare "Cannot read properties of undefined" pointing at the module
rather than at the fake. It is now `createDefaultDataTableState()`.
