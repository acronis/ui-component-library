## 3. What the integrator actually needs to do

**Nothing is blocking.** Two optional items:

1. **`packages/ui-spec/components/table/index.yaml` — a `since:` bump.** Per
   NB-4 no unit edits an `index.yaml`, and F3 did not. If the table component's
   `since:`/`status:` should record this release, that edit plus a
   `spec-index.json` regeneration is the integrator's, in one pass.

2. **`table.generated.stories.tsx` — already regenerated, zero diff.** NB-3
   assigns it to F3, so it was regenerated with
   `pnpm --filter @constructor-lab/ui-spec generate:stories`. The output is
   byte-identical to what is committed, because the generator only emits extra
   stories for `kind: pseudo` states and interactive transitions, and every
   state F3 added is `kind: prop`. Nothing to apply.

   **Caveat for whoever regenerates next.** The script takes no component
   filter — it rewrites all 56 generated story files and **creates four new ones**
   (`autocomplete`, `checkbox-group`, `meter`, `otp-field`, which have specs but
   no generated stories committed). F3 backed up every generated file first,
   restored all but `table`'s, and deleted those four. In a shared checkout,
   running it unguarded clobbers other units' in-flight generated stories.

## 4. One contract ambiguity, for the team lead

F3's **Owns** list reads
`packages/ui-spec/components/table/{api.yaml,anatomy.yaml,behavior.md}` — *via
the integration queue*, while §1.2 lists "any `packages/ui-spec/components/*/api.yaml`"
as a manifest file. Those two together are unsatisfiable alongside NB-3: F3 has
to regenerate the generated stories, and the generator reads `api.yaml` +
`anatomy.yaml`, so it cannot regenerate from blocks it has not applied.

F3 read the manifest-file rule as scoped to the files where units genuinely
collide (`data-table/behavior.md`, `data-grid/behavior.md`, and any `index.yaml`)
and edited the `table` spec directly, since no other unit in the plan opens it.
`tokens.yaml` was edited on the same reasoning. **If that reading is wrong, the
edits are confined to those four files and can be reverted and re-staged.**
