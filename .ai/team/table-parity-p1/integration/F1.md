````markdown
```gherkin
Scenario: [Target P1 — shipped legacy parity] Each expansion domain owns a different mechanism
  Given a row has both descendants and detail content
  When the tree domain expands the row
  Then its descendants enter the row model as record rows and are paginated with them
  And detail state is unchanged
  When the detail domain expands the same row
  Then a detail row is projected by the render layer after pagination
  And it consumes no pagination slot
  And it never appears in the row model, flatRows, or rowsById
  And tree state is unchanged
  And the row context exposes a detail namespace and a tree namespace, with the
    deprecated isExpanded/canExpand/toggleExpanded aliases meaning detail
```
````
