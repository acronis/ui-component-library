## 2. `packages/ui-react/src/components/ui/data-grid/data-grid-config/index.ts` — APPLIED

`columnsFeaturesConfig` is imported and sits in `DATA_GRID_CONFIG_MODULES`
**after `sortingConfig` and before `filtersConfig`**, for the reason recorded in
that file: resolving before `actions`/`selection` would compute
`lockedColumnIds` against a column set that does not yet contain the system
columns it locks.

**Note for whoever regenerates anything from that manifest:** the module file is
now `columns-features.tsx`, not `.ts` — it renders the header-control adornment
and the live region. The `.ts` was removed with `git mv` in the same commit,
because two files make `./columns-features` ambiguous and Vite and `tsc` resolve
it differently (the `footer.ts`/`footer.tsx` incident).

## 3. Public type re-exports — OUTSTANDING, barrel-only

These make the header-control contract reachable from the package. Nothing in the
repo needs them: `data-grid-config/columns-features.tsx` imports the engine types
by their internal path (`'../../data-table/data-table-features/columns'`), which
is the established pattern here — `data-grid-tree.tsx`, `data-grid-footer.tsx`,
`data-grid-detail-expansion.tsx` and `data-grid-callbacks.ts` all do the same.

Per the "two hops, not one" note on the merge-gate task: these types live in
`data-table-features/columns.tsx`, so they need a route to the package barrel.
Two options, integrator's choice:

- **Direct**, which needs no F2-owned file: add a new block to
  `data-table/index.ts`.

  // DataTable renders no handle and no live region.

  the barrel re-exports it from the controller). That touches an F2-owned file,
  so it needs F2 or the integrator.

`packages/ui-react/src/index.ts:29` is
`export * from './components/ui/data-table'`, so the root barrel needs no edit.

### 3b. `data-grid/index.ts` — the group's config types

In the `export { … } from './data-grid';` block (which is where every other
group's config type is re-exported from):

```ts

```

and, in `data-grid/data-grid.tsx`'s `export type { … } from './data-grid-config';`

## 4. Escalations — all three closed

1. **`ColumnPresentation` could not express pinning.** Closed: `pinned`/
   `pinOffset` are on `ColumnPresentation` and the view forwards them to
   `TableHead`/`TableCell`'s pin hook, so `data-pinned` is set and the z-ladder
   and row-tint rules apply. Landed in `5bf8173`.
2. **`edge` adornments landed inside the sort `<button>`.** Closed: `TableHead`
   gained a `trailing` slot (`76e4558`) and the view routes
   `adornmentsAt(presentation, 'edge')` to it. `378a6a14` then made the header
   name itself from its label region, so a labelled control in the slot is
   structurally excluded from the `<th>`'s accessible name.
3. **The column-settings menu overlapped `DataTableViewOptions`.** Closed:
   `data-grid-column-settings.tsx` replaced it in DataGrid's own toolbar row
   (`3fe524e`), with the sections gated by `columnsFeatures` (`462879d`).
   `DataTableViewOptions` stays exported for external callers.

## 5. Nothing else

- **No `data-table-features/index.ts` edit** — `columns` was created by F2 and is
  already in the manifest.
- **No `data-grid-callbacks.ts` edit** — `onColumnStateChange` and its four-slice
