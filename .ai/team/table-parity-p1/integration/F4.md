## 3. One file the plan does not list — and one it lists that F4 did not touch

**Created: `packages/ui-react/src/components/ui/data-grid/data-grid-toolbar.tsx`.**
DataGrid-private chrome, in the same class as `data-grid-column-filters.tsx` and
`data-grid-actions.tsx`. It exists because `toolbar.viewOptions` is a new feature
and `data-table/index.ts:98` marks the whole `DataTable*` companion suite "do not
add new features here" (design §1: the library publishes no batteries-included
DataTable companion suite; those pieces move behind DataGrid and are removed next
major). Design §5.2's unimplemented `toolbar.leading`/`trailing` members extend
this file.

The cost of that choice is divergence from the shared toolbar, so it is guarded:
`data-grid/__tests__/data-grid-toolbar.test.tsx` renders both through the same
controller and asserts identical markup at the default `viewOptions`, modulo
React/Base UI per-render ids. That test is what makes the visual baselines for
every unchanged DataGrid story safe.

**Not touched: `packages/ui-react/src/components/ui/data-table/data-table-toolbar.tsx`.**
The team lead granted it to F4 for an additive `viewOptions?: boolean` prop before
the freeze comment above came to light. F4 withdrew the request and the file is
byte-identical to `88eaf6b`. If the architect added it to F4's Owns list, it can
come off — the next unit to want it should read the freeze comment first.
