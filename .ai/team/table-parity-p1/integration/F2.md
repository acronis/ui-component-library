## 2. `packages/ui-spec/components/data-table/behavior.md`

**F2 satisfies no pre-existing target scenario, and that is expected**: the unit
has no user-visible payload, which is exactly why its acceptance rests on the
read-only guard set passing unmodified instead. The blocks below are therefore
*new* scenarios for the invariants F2 makes observable — offered for the
integrator (or tech-writer) to accept or drop, not claimed as delivered targets.

Both belong in `## Row-model pipeline`, after the existing
`Scenario: [Target P1] Virtualization is presentation only`.

```gherkin
Scenario: [Target P1 — new React hardening] A display-row kind without a renderer fails loudly
  Given the view derives a display-row list over the engine's record rows
  When a row kind is emitted that no feature renders
  Then the projection raises rather than rendering an empty row
  And record identity, pagination counts and keyboard order stay keyed to records
```

```gherkin
Scenario: [Target P1 — new React hardening] Two features cannot contend one contribution
  Given two internal features contribute to the same engine option or context field
  When the projection is composed
  Then composition raises and names both contributors
  And a single feature may still contribute several keys in one contribution
```
