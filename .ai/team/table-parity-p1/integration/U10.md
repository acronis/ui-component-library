## 0. The atom is THREE parts, not four — persistence has no chrome

Recorded because the brief asked the question explicitly and an unanswered "no
chrome" is indistinguishable from a forgotten one.

Persistence restores stored preferences **into slices other features own**. Its
config members are `key`, `version`, `storage`, `include`, `migrate` and
`onError`, and **every one is consumed by the DataTable restore engine** reached
through `controllerOptions` — so none is the "declared, reachable, and empty"
shape the fourth part of the atom exists to prevent. The *effect* of a restore is
visible only through chrome that already exists for the slice restored into: a
hidden column, a column width, a sort indicator. There is no control a caller
would press to persist something.

So U10's atom is: the config module, its `declare module` registry augmentation,
and the manifest line — **one commit**, for the reasons in
`data-grid-config/README.md` ("There is no half-landed state").

**Why this hop exists**, and — corrected after checking rather than asserting —
**exactly what it does and does not fix.**

## 2.1 Manifest position, and why it is where it is

`persistenceConfig` goes **after `toolbarConfig`, before `stateConfig`**.

- Position is otherwise free: the group contributes **no `columns` transform**, so
  it takes no place in the column fold, and its `resolve` reads only its own
  prop — nothing from `resolved`.
- Placed last-but-one to mirror the DataTable side, where `FEATURE_ORDER` puts
  `persistence` last "because it restores into the slices every other feature
  owns" (`data-table-features/registry.ts:72`). Keeping the two registries' stories
  the same is worth more than an arbitrary earlier slot.
- **`state` must stay last.** Its own docblock and the order pin both require it,
  because it merges what every earlier module resolved. Persistence contributes
  nothing `state` reads, so sitting in front of it changes nothing for it.

### Expected visual-baseline churn (for W3-VISUAL, #48)

**Exactly four new DataGrid stories** — `Persistence/NothingStored`,
`RestoredColumnPreferences`, `RestoredSorting`, `StalePayloadDiscarded`. **Any
change to any pre-existing DataGrid or DataTable story PNG is a defect, not
churn**: `persistence` renders nothing, contributes no `columns` transform and no
`viewProps`, so it cannot alter the rendering of a grid that does not enable it.

Two of the four are worth knowing about before reviewing them:

- **`NothingStored` and `StalePayloadDiscarded` should be pixel-identical to each
  other.** That is the point of the pair — a discarded payload must leave a grid
  looking exactly like one with nothing stored. If they differ, a stale payload is
  partially restoring.
- **Neither can be verified by screenshot alone**, which is why the discard is
  asserted in `__tests__/data-grid-persistence.test.tsx` and the engine suite
  rather than left to the baseline.
