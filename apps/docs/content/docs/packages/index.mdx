`@spec-lab/ui-react` does not stand alone. It sits on top of a small
ecosystem of published packages that carry the design data, generate the
themeable CSS, and ship the icons. This section documents those building
blocks so you can consume them directly or understand how a token or icon
flows from design into a component.

## The pipeline

Design data curated in Figma flows through build tooling into the consumable
packages:

- `@spec-lab/tokens` holds the DTCG source `tiers/*.json` **and** the generated,
  committed output. `tools/style-dictionary` builds the tiers into the same
  package's reference-based `css/` + `scss/` + `js/` (+ the Tailwind bridge and a
  DTCG intermediate).
- `@spec-lab/icons-react` is generated from the `@spec-lab/icons-svg` SVG
  sources by the icon generator (tree-shakeable React components).
- `@spec-lab/design-assets` ships icon / illustration JSON manifests + bundled
  binaries (an optional data package).

Finally, `@spec-lab/ui-react` consumes `@spec-lab/tokens` for theming and
`@spec-lab/icons-react` for composed icons.

```
tokens/tiers   ─►  tools/style-dictionary  ─►  tokens (css/scss/js) ─┐
                                                                     ├─► ui-react
icons-svg ─►  icon generator          ─►  icons-react ──────────┘
```

## Published packages

| Package                   | Ships                                                     | Published |
| ------------------------- | --------------------------------------------------------- | --------- |
| `@spec-lab/tokens`        | DTCG source tiers + generated CSS/SCSS/JS (`--ui-*` vars) | yes       |
| `@spec-lab/icons-react`   | React icon components, per-pack subpath exports           | yes       |
| `@spec-lab/design-assets` | Icon / illustration JSON manifests + bundled binaries     | yes       |

<Callout type="info">
  The source SVG packages (`icons-svg`, `icons-svg`), the tooling under
  `tools/`, and the apps (`demo`, `docs`, `kitchen-sink`) are **private** and
  not published. Only the five packages above are on npm.
</Callout>
