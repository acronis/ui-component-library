The sanctioned way to run a short, guided multi-step task without leaving the
page: a **`Dialog`** whose header carries a **`Progress`** step indicator, whose
body swaps **`Form`** content per step, and whose footer navigates with Back /
Next and a final Finish. The dialog stays mounted across steps so entered values
persist; only the visible step's fields change. Reserve it for flows that are
genuinely staged — 2 to a few steps — where splitting the input reduces
cognitive load.

## When to use

- A guided setup/onboarding with 2–a few discrete steps in a fixed order.
- Breaking a longer form into digestible stages with a visible progress cue.
- A flow where later steps depend on earlier answers but the whole thing is
  short.

## When not to use

- A single step — use `form-dialog`.
- A long or branching linear flow better as a full-page route with its own URL
  per step.
- A yes/no confirmation — use `confirm-dialog`.

## Composition

```tsx
function SetupWizard({ open, onOpenChange, onFinish, steps }) {
  const [step, setStep] = React.useState(0);
  const isLast = step === steps.length - 1;
  return (
    <Dialog open={open} onOpenChange={onOpenChange}>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>{steps[step].title}</DialogTitle>
          <Progress value={((step + 1) / steps.length) * 100} />
        </DialogHeader>
        <Form onFormSubmit={() => (isLast ? onFinish() : setStep((s) => s + 1))}>
          <DialogBody>{steps[step].content}</DialogBody>
          <DialogFooter>
            <Button
              variant="ghost"
              type="button"
              disabled={step === 0}
              onClick={() => setStep((s) => s - 1)}
            >
              Back
            </Button>
            <Button type="submit">{isLast ? 'Finish' : 'Next'}</Button>
          </DialogFooter>
        </Form>
      </DialogContent>
    </Dialog>
  );
}
```

## Guidelines

- Keep the dialog mounted and preserve state across steps — remounting or
  unmounting steps loses entered data.
- Always show the `Progress` indicator so the user can tell how many steps
  remain.
- Gate advancement on the current step's `Form` validation — don't allow Next
  while the step is invalid.
- If it's really one step, it's a `form-dialog` — don't cram every field into a
  single faked wizard.
