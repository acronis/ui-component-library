The sanctioned way to build an authentication screen: **`AuthLayout`** centers
the page and holds an **`AuthLayoutCard`** framing a short form of **`InputText`**
fields and a full-width primary **`Button`**, with a **`Link`**
(forgot-password / switch to sign-up) in the `AuthLayoutFooter`. One recipe
covers sign-in, sign-up, and reset — only the fields, the submit label, and the
footer link change. It composes existing components rather than a bespoke login
screen.

## When to use

- Any unauthenticated entry screen — sign-in, sign-up, password reset, MFA
  challenge.
- A short, focused form the user completes before entering the app.
- Keeping the branding + form centered and consistent across all auth variants.

## When not to use

- A settings or profile form inside the authenticated app — use a page layout,
  not `AuthLayout`.
- A multi-step onboarding flow — use `wizard-dialog` or a routed sequence.
- A modal credential prompt over existing content — use a `Dialog`.

## Composition

```tsx
function SignInScreen({ onSubmit }) {
  return (
    <AuthLayout>
      <AuthLayoutCard>
        <AuthLayoutLogo>
          <span className="text-base font-semibold">Sign in</span>
        </AuthLayoutLogo>
        <Card>
          <CardContent>
            <form className="flex flex-col gap-4" onSubmit={onSubmit}>
              <InputText label="Email" type="email" placeholder="you@example.com" required />
              <InputText label="Password" type="password" required />
              <Button type="submit" className="w-full">Sign in</Button>
            </form>
          </CardContent>
        </Card>
        <AuthLayoutFooter>
          <Link href="/reset">Forgot password?</Link>
        </AuthLayoutFooter>
      </AuthLayoutCard>
    </AuthLayout>
  );
}
```

## Guidelines

- Compose `AuthLayout` instead of hand-centering a card with ad-hoc flexbox —
  you'd lose the shared logo/footer slots and responsive framing.
- Keep the card to the essential fields; defer everything else to inside the
  app.
- Use `Link` for the footer link, not a raw `<a>`, so focus-ring and color
  tokens carry through.
- Make the submit button full-width primary — the single obvious action is the
  point.
